**GRIME** — это быстрый консольный оркестратор для разработчика на Linux. Он связывает управление проектами, изолированные окружения Nix Flakes, контейнеры Distrobox, системные пакетные менеджеры и AI-ассистента Aider в единый предсказуемый инструмент командной строки.

Главная цель GRIME — избавить основную систему от беспорядка. Вместо того чтобы ставить десятки компиляторов, библиотек и разовых утилит прямо на хост, вы запускаете и собираете код в изолированных воспроизводимых средах одной короткой командой.

---

## Зачем нужен GRIME и какую проблему он решает

При активной разработке на нескольких языках (C++, Rust, Python, Java, Lua) рабочая система быстро обрастает конфликтующими зависимостями, разными версиями компиляторов и забытыми пакетами. Для решения этой проблемы обычно используют Nix, контейнеры Podman/Distrobox и разные сборочные скрипты, но у каждого из них свой синтаксис и свои особенности.

GRIME убирает эту рутину:
- **Чистая хост-система.** Если программа или компилятор нужны на один раз, GRIME прозрачно запустит их через Nixpkgs или внутри контейнера Distrobox, не оставляя следов в системе.
- **Автоматический подбор тулчейна.** Достаточно открыть папку с кодом и вызвать сборку — сканер сам определит языки проекта, сгенерирует окружение Nix Flake в кэше (`~/.cache/grime/`) и соберёт проект без засорения репозитория лишними файлами.
- **Единый язык команд.** Вам не нужно помнить десятки флагов `cmake`, `cargo`, `javac`, `nix` или `distrobox`. Все операции с проектами, сервисами, пакетами и Git подчиняются одной логике.
- **Настоящие конвейеры данных.** Разные модули можно выстраивать в цепочки в одну строку: найти путь к проекту, переключиться в контейнер Fedora, собрать бинарник, вернуться на хост и запустить его.

## Философия и принцип работы

Архитектура GRIME строго разделена на два уровня: **нативное микроядро на Rust** и **декларативные модули на LuaJIT**.

```mermaid
flowchart LR
    CLI["CLI (grime)"] -->|Unix Socket IPC| Daemon["Фоновый демон (Rust + Tokio)"]
    Daemon --> Pool["Пул виртуальных машин LuaJIT"]
    Daemon --> Bus["Шина состояния (StateBus)"]
    Pool --> Modules["Модули (project, app, pkg, nix, box, git, aider...)"]
    Modules --> Env["Среды: Хост / Nix Flake / Distrobox"]
```

1. **Микроядро на Rust (`grime`)**
   Ядро намеренно не содержит привязанной к конкретным утилитам бизнес-логики. Его задача — максимально быстро разобрать командную строку, передать аргументы нужным модулям, выстроить конвейер шагов, обеспечить потокобезопасный обмен данными через шину состояния (`StateBus`) и централизованно обработать ошибки. При остановке любого шага ядро выводит сообщение об ошибке ровно один раз и аккуратно прерывает конвейер.
2. **Фоновый демон и пул LuaJIT VM**
   Демон удерживает в оперативной памяти прогретый пул виртуальных машин LuaJIT и текущее состояние шины (потребляя всего 4–6 МБ RAM). Когда вы вводите команду `grime`, лёгкий клиент связывается с демоном через Unix-сокет за доли миллисекунды. Если демон не запущен, любая команда прозрачно выполнится напрямую в текущем процессе.
3. **Прикладные модули (`modules/*.lua`)**
   Вся логика работы с компиляторами, пакетами, Git, контейнерами и AI живёт в модулях на LuaJIT. Модули редактируются на лету без перекомпиляции ядра, используют общую библиотеку парсинга аргументов (`languages/argparse.lua`) и безопасный нативный API ядра (`grime.ctx`, `grime.fs`, `grime.process`, `grime.bus`, `grime.fuzzy`).

## Единый стандарт команд, флагов и конвейеров

Чтобы интерфейс оставался интуитивным во всех модулях, в GRIME действует единый стандарт синтаксиса:

- **Все флаги и действия начинаются со знака минус (`-` или `--`).**
  Например: `-list` (`-ls`), `-path` (`-p`), `-new` (`-n`), `-build` (`-b`), `-run` (`-r`), `-rm`, `-update` (`-u`), `-help` (`-h`). Короткие и полные формы взаимозаменяемы.
- **Свободный порядок сущности и флага.**
  Вы можете писать как `grime project -path grime_pj`, так и `grime project grime_pj -path` — оба варианта сработают одинаково и найдут проект даже по неполному имени (fuzzy-поиск).
- **Разделитель аргументов `//` (или `--`).**
  Если нужно передать внешней программе её собственные флаги, чтобы ядро GRIME их не перехватывало, поставьте перед ними `//`:
  ```bash
  grime cmd // echo -n "проверка"
  grime pkg -run // ffmpeg -i input.mp4 output.webm
  ```
- **Конвейеры модулей через двоеточие `:`.**
  Шаги в одной команде соединяются знаком `:` (в оболочке Fish символ `->` является перенаправлением в файл, поэтому `:` — основной и безопасный разделитель). Каждый шаг автоматически передаёт следующему рабочую директорию (`target_dir`), возвращаемый результат (`pipeline_input`) и данные через `StateBus`:
  ```bash
  grime project -path MyService : git -status : bus -set build.ready true
  ```
- **Переключение сред (`box` / `nix` и возврат через `host`).**
  Модуль `host` служит рубежом, который возвращает выполнение из контейнера Distrobox или окружения Nix обратно на основную ОС:
  ```bash
  grime project -path MyEngine : box fedora-box : project -build : host : project -run
  ```

## Основные модули и примеры использования

### 1. Оркестратор проектов (`project`)
Управление проектами разработки на C++, Rust, Python, Java и Lua. Поддерживает нечёткий поиск папок, автоопределение системы сборки и проверку времени изменения исходников (`mtime`) перед запуском.

```bash
# Создать новый проект на выбранном языке
grime project -init rust fast_proxy
grime project -init cpp render_core

# Найти путь к проекту (удобно для быстрого перехода в директорию)
cd (grime project -path grime_pj)

# Собрать и запустить проект (пересборка запустится только если код изменился)
grime project -build grime_pj
grime project -run grime_pj

# Показать список всех проектов
grime project -list
```

### 2. Локальные микроприложения (`app`)
Создание и запуск собственных утилит и сервисов, каждый из которых живёт в своей директории с манифестом `app.lua` и собственным окружением `flake.nix`.

При создании приложения (`-new`) вы можете просто описать задачу человеческим языком: GRIME сам распознает нужный стек (`python`, `java`, `rust`, `lua`, `cpp`) прямо из текста промпта, развернёт шаблон и поручит Aider написать рабочий код.

```bash
# Создать приложение с автовыбором стека из текста описания
grime app -new WeatherCli "консольное приложение на Python для вывода погоды"
grime app -new LogParser "утилита на Rust для фильтрации логов"
grime app -new StoreApi "сервис учёта заказов на Java"

# Получить путь к папке приложения или к корневому каталогу всех аппов
grime app -path WeatherCli
cd (grime app -path)

# Собрать и запустить приложение (в том числе в фоновом режиме демона)
grime app -build WeatherCli
grime app -run WeatherCli
grime app -run LogParser -detach

# Посмотреть активные фоновые сервисы и остановить нужный
grime app -ps
grime app -stop LogParser

# Упаковать приложение со всеми библиотеками в автономный бинарник в папке dist/
grime app -bundle WeatherCli

# Сделать снимок состояния в Git, посмотреть двойной дифф (Git + Nix) или откатить изменения
grime app -snapshot WeatherCli "рабочая версия"
grime app -diff WeatherCli
grime app -rollback WeatherCli
```

### 3. Единый менеджер пакетов и утилит (`pkg`)
Объединяет работу с пакетными менеджерами хоста (`pacman`, `yay`, `dnf`, `apt`), `flatpak`, профилем `nix`, `cargo`, `pipx` и контейнерами `distrobox`.

```bash
# Сводная таблица по всем активным пакетным менеджерам системы
grime pkg

# Посмотреть установленные пакеты конкретного менеджера
grime pkg -pacman
grime pkg -yay
grime pkg -flatpak
grime pkg -nix

# Сквозной нечёткий поиск установленного пакета сразу везде
grime pkg ripgrep

# Установка и удаление пакетов
grime pkg -yay -install neovim
grime pkg -nix -install jq
grime pkg -flatpak -remove org.gimp.GIMP

# Обновление конкретного менеджера или всей системы целиком (yay/pacman + flatpak + nix + distrobox)
grime pkg -update -yay
grime pkg -update

# Разовый запуск любой программы без установки на хост (каскад: локально -> Distrobox -> эфемерный Nix)
grime pkg -run cmatrix
grime pkg -run -y // ffmpeg -version
```

### 4. AI-ассистент разработки (`aider`)
Интеграция AI-агента Aider в рабочий процесс GRIME. Модуль знает структуру ваших проектов и приложений, умеет принимать вывод предыдущих шагов конвейера, анализировать ошибки последнего запуска в терминале и генерировать новые модули GRIME строго по архитектурному стандарту.

```bash
# Запустить Aider в директории проекта по его имени
grime aider grime_pj "оптимизируй парсинг аргументов"

# Передать контекст из конвейера в Aider
grime project -path grime_pj : git -diff : aider -m "проверь изменения и напиши сообщение для коммита"

# Создать новое приложение с нуля через Aider (с автоопределением языка из промпта)
grime aider -app JsonTool "сделай утилиту на Python для форматирования JSON"

# Создать или доработать модуль самого GRIME по стандарту (с автопроверкой luajit -bl и синхронизацией)
grime aider -module netstat "модуль для просмотра открытых портов"
```

### 5. Изолированные окружения Nix (`nix`) и контейнеры (`box`)
```bash
# Выполнить команду в эфемерном окружении Nix DevShell для текущего проекта
grime project -path grime_pj : nix -exec // cargo test

# Управление профилем и хранилищем Nix
grime nix -history
grime nix -gc
grime nix -optimise

# Список контейнеров Distrobox и запуск команд внутри контейнера
grime box -list
grime box fedora-box -run dnf search clang
grime box -export bin /usr/bin/htop
```

### 6. Инфраструктура: Реестр (`list`), Git (`git`), Шина (`bus`), Диагностика (`doctor`)
```bash
# Обзор всей экосистемы (модули, приложения, проекты)
grime list
grime list -modules
grime list -apps
grime list -projects

# Работа с Git в конвейере
grime project -path grime_pj : git -status
grime project -path grime_pj : git -snapshot "перед рефакторингом"

# Обмен данными через шину состояния StateBus
grime bus -set deploy.env production
grime bus -get deploy.env
grime bus -list

# Проверка здоровья системы, путей, сокета демона и логов
grime doctor
grime daemon -status
grime log -list -n 20
```

## Сборка и установка

### Сборка через Nix Flake (рекомендуется)
```bash
nix build .#static
# или вход в окружение разработки:
nix develop
```

### Сборка через Cargo
```bash
cargo build --release
cp target/release/grime ~/.local/bin/
```

После копирования бинарника в `~/.local/bin/` перезапустите фоновый демон и проверьте окружение:
```bash
grime daemon -restart
grime doctor
```

Для автоматического перехвата неизвестных команд в оболочке Fish добавьте в `~/.config/fish/functions/fish_command_not_found.fish`:
```fish
function fish_command_not_found
    grime pkg -not-found $argv
end
```
