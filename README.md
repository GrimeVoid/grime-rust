# Grime Next Generation (Grime-RS) 🦀🌙

> **Высокопроизводительный модульный CLI/демон-оркестратор рабочих пространств, контейнеров (Distrobox), воспроизводимых Nix-окружений и процессов разработчика.**

Переписанное ядро на **Rust** с декларативной расширяемостью через **Lua (LuaJIT / mlua)** и опциональным фоновым демоном (`grimed`) для мгновенного отклика (1–2 мс), сохранения контекста сессий и Hot-Reload модулей.

---

## ⚡ Ключевые особенности

- **Экстремальная производительность**:
  - Холодный старт CLI: **~3.6 мс** (в 23 раза быстрее оригинальной версии на Python).
  - Отклик через Unix Domain Socket демона: **~1-2 мс**.
  - Потребление памяти демоном в простое: всего **~4.2 МБ RAM**.
- **Двухуровневая архитектура (Client-Daemon & Direct Fallback)**:
  - Автономный клиент `grime` автоматически обращается к сокету `/run/user/$UID/grime.sock`.
  - При отсутствии демона прозрачно переключается на прямой `in-process` запуск без задержек.
- **Шина данных в памяти (Shared State Bus)**:
  - `grime.bus`: Потокобезопасный обмен структурированными данными между шагами и модулями через RAM без строкового парсинга.
  - Автоматическая RAII-очистка пространства `pipeline.*` после каждого запуска.
- **Контроль ресурсов и Zero-Copy**:
  - `bytes::Bytes` Zero-Copy Payload для передачи буферов между шагами без лишних аллокаций.
  - Предохранитель от бесконечных циклов в Lua (`lua_sethook` + `CancellationToken`).
  - Перехват `Ctrl+C` (SIGINT) и автоматический вызов `cleanup()` у задействованных модулей.
- **Упреждающий прогрев окружений (Pre-flight Inspection)**:
  - Анализ графа шагов перед выполнением: упреждающий асинхронный запуск контейнеров Distrobox в фоне через Tokio. При переходе к контейнеру — **0 мс задержки**.
- **Событийная шина (Event Bus)**:
  - `grime.events.on(event, callback)` и `grime.events.emit(event, data)`. Хуки жизненного цикла: `pipeline.start`, `pipeline.step.start`, `pipeline.finish`, `pipeline.failed`.
- **Декларативные Lua-модули и Hot-Reload**:
  - Мгновенная перезагрузка модулей через `notify` при сохранении файла без перезапуска демона.
  - Ввод аргументов и промптов без кавычек.

## 📦 Модули системы

| Модуль | Описание |
| :--- | :--- |
| **`project`** | Полный жизненный цикл проектов (`init`, `build`, `run`, `delete`, `path`, `clear`) с языковыми шаблонами (C++, Rust, Python, Java). |
| **`box`** | Оркестрация Distrobox-контейнеров (`list`, `enter`, `run`, `export`). |
| **`nix`** | Декларативные Nix Flakes, временные окружения `shell.nix`, очистка `gc`, дедупликация `optimise`. |
| **`pkg`** | Универсальный мета-менеджер пакетов (`pacman`, `flatpak`, `nix`, `distrobox`, `cargo`, `pipx`). |
| **`aider`** | Интеграция с AI-ассистентом: интерактивный чат, пакетный режим без кавычек и Prompt Chaining (`<next_agent_prompt>`). |
| **`cmd`** | Прямой запуск команд хоста и TUI-утилит (`fzf`, `nvim`). |
| **`host`** | Модуль-рубеж для возврата на хост-машину из изолированных слоёв. |

## 🚀 Сборка и установка

### Через Nix Flake (Рекомендуемый способ)

```bash
# Сборка полностью автономного статического бинарника (musl libc):
nix build .#static

# Или запуск временного dev-окружения:
nix develop
```

### Стандартная сборка через Cargo

```bash
cargo build --release
```

Готовые бинарники будут расположены в:
- `target/release/grime` — CLI-клиент
- `target/release/grimed` — Фоновый демон

## 💡 Примеры использования

```bash
# Инициализация C++ проекта, генерация кода через AI и сборка в Fedora Distrobox:
grime project cpp init MyGame path : aider -m напиши змейку на ncurses : box fedora-box : project build : host : project run

# Запуск команд через конвейер данных:
grime project rust QuickCLI path : cmd cargo check : cmd echo "Готово!"

# Одноразовый запуск утилиты в изолированном Nix-окружении:
grime pkg try cowsay "Привет из Grime Next Gen"
```

### 🐚 Синтаксис конвейеров и особенности командных оболочек (Fish Shell)

Grime поддерживает несколько символов для разделения шагов конвейера:
- `:` (двоеточие) — **рекомендуемый универсальный разделитель** для всех оболочек.
- `--` (двойной дефис).
- `->` (стрелка).
- `|` (пайп, требует экранирования в шелле).

> **Важно для пользователей Fish Shell:**
> В оболочке Fish токен `->` воспринимается как оператор перенаправления вывода в файл (символ `>` создает файлы с именами последующих команд, например `~/bus` или `~/git`).
> Для корректной работы в Fish shell используйте **двоеточие `:`** или берите стрелку в кавычки (`"->"`):
> ```fish
> # Рекомендуемый синтаксис в Fish:
> grime host : bus set host.flag active : git status : log INFO "Telemetry audit" : doctor : bus get host.flag
> ```
